# Implementation Plan: Glotty Phase 1 MVP

## Goal Description
Build the foundational architecture and Phase 1 MVP of **Glotty** as specified in [`Glotty_Concept.md`](file:///Users/webadmin/Work/Glotty/Glotty_Concept.md). 

Glotty is an adaptive language learning system where *"the learner is the curriculum"* and the core product promise is earned insight: **"We noticed something about you."** Phase 1 proves the dual-path evaluator and the insight discipline for B1 English speakers learning Spanish, targeting two concept clusters:
1. **Preterite vs. Imperfect** (`es.gram.aspect.pret_imp`)
2. **Por vs. Para** (`es.sem.por_para`)

---

## Approved Tech Stack & Architecture Decisions

> [!IMPORTANT]
> **User-Approved Technical Configuration:**
> - **LLM Provider:** **Gemini 1.5 Flash** (`@google/genai` or `@google/generative-ai`) for asynchronous diagnostic evaluation and conversational generation.
> - **Database:** **Local PostgreSQL 17** (`postgresql@17` on port 5432, dedicated DB `glotty`). Strictly **no Docker** and **no SQLite**.
> - **ORM & Migrations:** **Drizzle ORM** (`drizzle-orm` + `drizzle-kit`). All database schema changes and migrations must strictly run through `npx drizzle-kit generate` and `npx drizzle-kit migrate` (**no manual migrations**).
> - **Authentication:** **Better Auth** (`better-auth`) integrated with Next.js and Drizzle schema for user, account, and session management.
> - **Application Architecture:** **Next.js (App Router, TypeScript, Tailwind CSS)** for fullstack UI and server-side API routes (`/api/...`).
> - **Language Intelligence & Morphology:** Morphological and fast NLP validation on the sync path utilizing Spanish linguistic rules + companion Python service/CLI (`spaCy` `es_core_news_md`) for gold-standard gate evaluation.

### Milestone 2: Gold Standard Benchmark Suite & Dual-Path Evaluator (§21–§26)
1. Build Gold Standard benchmark dataset (`data/gold_set/spanish_b1_gold.json`) with annotated learner responses.
2. Implement **Synchronous Evaluator** (<200ms budget, zero LLM):
   - Fast answer key match & Unicode normalization.
   - Morphological form validation for Spanish irregular & regular preterite, imperfect, and por/para prepositions.
   - Returns `CORRECT`, `INCORRECT`, or abstains to `UNCERTAIN`.
3. Implement **Asynchronous Evaluator**:
   - Server-side Gemini 1.5 Flash client with Appendix B diagnostic taxonomy definitions, negative examples, and contrastive checks.
   - Charitable intent interpretation (§21).
   - High-precision classifier: if model confidence < 0.70 or intent is ambiguous, returns `UNCERTAIN` to enforce precision on `INCORRECT` $\ge 0.95$.
4. Acceptance Gate Test Suite (`tests/evaluator_benchmark.test.ts`):
   - Evaluates on held-out gold set: binary accuracy $\ge 0.90$, precision on INCORRECT $\ge 0.95$, diagnostic top-1 $\ge 0.65$, `UNCERTAIN` rate $\le 15\%$.

### Milestone 3: Probabilistic Learner Model & Evidence Weighting (§13–§17, §35)
1. Probabilistic state representation per concept across 5 competence levels:
   - Recognition, Contextual Understanding, Recall, Production, Spontaneous Use (§14).
2. Beta-distribution belief state tracking: mean $\mu$, variance $\sigma^2$, sample count $N$.
3. Evidence weighting implementation (§16):
   - Controlled item (1.0), Constrained production (0.8), Free conversation (0.4), Reading (0.6), Long gap (1.2), Uncertain eval (0.1).
4. Deterministic state replay function: reconstructs any learner's state at any historical timestamp $T$ purely from immutable `events`.

### Milestone 4: Policy, Exploration Engine & Propensity Logging (§27–§30)
1. Rule-based action selector choosing next intervention (`review`, `explain`, `contrast`, `produce`, `read`, `conversation`, `nothing`).
2. First-class exploration engine (§29):
   - Near-tie action randomization within margin $\epsilon$.
   - Randomized explanation styles: `rule_based`, `conceptual`, `contrastive`, `etymological`, `cross_linguistic`, `example_first`.
   - Retention scheduling jitter ($\times 0.7$, $1.0$, $1.4$).
   - Control cohort assignment (Arm A adaptive vs Arm B fixed sequence, §44).
   - Strict requirement: Every event recorded in Postgres contains non-null `policy_candidates`, `propensity`, and `is_exploration`.

### Milestone 5: Insight Gate & Hedging Engine (§8–§12)
1. Rigorous implementation of §9 table:
   - Posterior probability $p \ge 0.75$.
   - Independent supporting observations $\ge 4$.
   - Distinct activity types $\ge 2$.
   - Distinct sessions spanned $\ge 2$.
   - Leading counter-hypothesis actively probed $\ge 1$ time.
   - Evaluator confidence on supporting items $\ge 0.7$.
2. Register selection (§10):
   - **Unhedged** ($p \ge 0.85$): direct observation.
   - **Hedged** ($0.75 \le p < 0.85$): tentative framing with verification probe.
3. Safety circuit breaker (§11): halts insight surfacing if user ratings of "this is wrong" exceed 3%.

### Milestone 6: Next.js UI & Interactive Sessions

   - Session 1 Cold-Start experience (§12, §43) offering linguistic framing rather than premature learner claims.
   - Transparent Learner Model Inspector (§39) showing estimates and uncertainty bars.
   - Post-session debriefing cards with hedged/unhedged insight presentation and 3 feedback buttons: *useful*, *not useful*, *this is wrong*.
2. API Routes:
   - `/api/auth/[...all]`: Better Auth handler.
   - `/api/session/start`: begins session with goal setting.
   - `/api/session/turn`: handles input, triggers sync evaluation (<200ms), triggers async Gemini evaluation.
   - `/api/session/end`: evaluates gate and precomputes post-session insights.
   - `/api/learner/profile`: returns learner model state and uncertainty.
   - `/api/insights/feedback`: records learner ratings.
